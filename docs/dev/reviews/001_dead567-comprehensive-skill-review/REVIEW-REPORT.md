## Canonical findings

### R-001 — State the scientific completion guarantee directly

| Field | Evidence |
| --- | --- |
| Baseline location | `technical-writing-assistant/references/scientific-writing.md:36`, completion checks. |
| Observation | The final sentence describes an editorial pass as not being represented as “unperformed data analysis or external verification.” The qualifier attaches awkwardly to the activity being represented rather than directly prohibiting an unsupported claim that the activity occurred. |
| Consequence | A directly loaded module makes its completion guarantee harder to interpret than necessary. Adjacent scope and output instructions already state the intended boundary correctly, so the expected impact is local and small. |
| Bounded correction owner | Scientific-writing module only. State that editorial work must not imply that data analysis or external verification occurred when it did not. No broader policy change or new gate is needed. |
| Suggested wording | “An editorial pass does not imply that data analysis or external verification was performed.” |
| Objective recheck | Read the replacement beside the module's inputs and outputs and confirm they agree about editorial assessment versus analysis/verification actually performed. Check that genuine separately authorized analysis is not denied or relabeled. |
| Disposition | Open. This report proposes the correction; it does not implement it. |

### R-002 — Avoid implying that untested conditions excluded an effect

| Field | Evidence |
| --- | --- |
| Baseline location | `README.md:32–36`, illustrative revision. |
| Observation | Both the input and output say lower losses occurred “only under dry conditions,” then say humid conditions were not tested. “Only” can describe the limit of the observation, but can also suggest that other conditions were evaluated and did not show improvement. The example does not resolve that reading. |
| Consequence | An example intended to demonstrate faithful, qualified revision may suggest unsupported exclusivity. This is an ambiguity, not proof that the pilot claim is false. The revision preserves the original input's wording; it is not evidence of a newly introduced meaning shift. |
| Bounded correction owner | README example and its explanation. Clarify the intended observation in both illustrative input and output, rather than silently strengthen or weaken one side. |
| Suggested direction | Describe losses observed in dry-condition testing and separately retain that humid performance was not tested. Keep the sample size and avoid adding a comparator, magnitude, significance claim or humidity result. |
| Objective recheck | Compare the two example versions for sample size, condition and testing limits. Ask whether a reader could still infer a tested negative result under humidity. Preserve the illustrative, non-trial label. |
| Disposition | Open recommendation. Resolve the intended meaning before revising the pair. |

## Consequential interfaces

- Entry-to-reference discovery is direct and complete. Need descriptions and selected-reference scopes make the owners intelligible without an unrelated reference search.
- Focused operations use appropriate guidance without requiring the complete manager or a questionnaire. Composite recipes select relevant work; they do not force repairs to sound material.
- Non-research work can acquire an explicitly requested target while citation-only retrieval and corroboration remain excluded. Explicit retrieval restrictions still govern target acquisition.
- Provenance/access, source support, researched-claim outcomes and requirement outcomes remain separate. Missing or non-addressing material is not disproof.
- Outline context exploration, generation and combined review have distinct responsibilities. Validation-only work need not trigger an unsolicited redesign.
- Composition analysis diagnoses unavailable referents; revision checking covers introduced or relevant previously diagnosed reference problems without banning words such as “previous.”
- Revision checking compares changed material with source/notes and authority, skips findings-only work and reports unavailable fidelity comparisons. It does not require an independent second comprehensive review of every original claim.
- Software, scientific and professional references preserve implementation/reporting/commitment status. Existing project docstring conventions govern; Google style is the Python fallback rather than a forced conversion.

These are inspected instruction relationships. The task observations below support only their sampled applications.
